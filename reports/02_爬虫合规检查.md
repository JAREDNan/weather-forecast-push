## 一、⚠️ 蓝本城市代码错误（最高优先级，已纠正）

需求蓝本 PDF 与提示词 §11 均写「聊城城市 ID = `101120701`」。**经实际请求核实，这是错的。**

| 项目 | 蓝本所写 | 实测正确值 | 核实方式 |
|---|---|---|---|
| 聊城市 / 东昌府区 城市代码 | `101120701` ❌ | **`101121701`** ✅ | 请求 `http://d1.weather.com.cn/sk_2d/101121701.html`，返回 `"cityname":"聊城","city":"101121701"` |
| `101120701` 实际对应 | — | **济宁市** | 中国天气网聊城页「周边城市」栏目中 `101120701` 明确标注为「济宁」 |

若按蓝本原样编码，系统将每天推送**济宁市**的天气却署名为聊城——这是会造成实际误导的严重错误，已在代码与配置中全部纠正为 `101121701`。

**关于「东昌府区」的粒度说明（重要）**：中国天气网体系中 `101121701` 是**聊城市本级（城区）**，其「本地乡镇」栏目下挂的北城街道、古楼街道、东城街道、湖西街道、凤凰街道、道口铺街道、蒋官屯街道、侯营镇、梁水镇、斗虎屯镇、广平乡、韩集乡**全部属于东昌府区**（东昌府区是聊城市唯一市辖区、市政府驻地，聊城主城区即东昌府区）。因此：

- ✅ **官方源（weather.com.cn / nmc.cn）没有独立的「东昌府区」代码，`101121701` 即覆盖东昌府区主城区**，这是目前能拿到的最细官方粒度，符合本项目「聊城某高校」的定位。
- ⚠️ 若未来需要精确到某个校区所在街道（如聊城大学位于东昌府区湖南路/文化路一带），可下钻到街道级页面 `http://forecast.weather.com.cn/town/weather1dn/1011217010XX.shtml`（实测这些 URL 真实存在，如古楼街道=`101121701006`、东城街道=`101121701003`）。
- ⚠️ **和风天气的 LocationID 与上述 9 位代码不是同一套体系，不可混用。** 和风天气的东昌府区 LocationID **⚠️ 未核实**，必须持有 API Key 后通过 GeoAPI 查询，见本报告第六节。

### 关键工程结论

1. **`d1.weather.com.cn` 三个接口全部实测可用、返回稳定、体积极小、且是 JS 变量而非 HTML DOM**——只需简单字符串截取 + `json.loads`，无需 BeautifulSoup，完全符合提示词 §4.2「优先 API 而非 HTML 解析」的要求。**推荐作为主采集通道。**
2. **nmc.cn 的 `rest/weather`、`rest/real` 已失效（返回空 data）**，网上大量教程仍在引用这两个端点，照抄必踩坑。nmc.cn 应改用：`rest/province/ASD`（城市索引）+ `rest/findAlarm`（预警）+ 预报页 HTML（必要时）。
3. **nmc.cn 页面标注「数据来源 中央气象台」**，weather.com.cn 页面同样标注「数据来源 中央气象台」——两者同源，weather.com.cn 是**中国气象局公共气象服务中心**主办的对外服务门户，符合《气象法》第二十五条「气象主管机构所属的气象台站提供」的要求，可合法作为文案署名来源。
4. **气象站号 `54806` = 聊城**（从 nmc.cn 聊城预报页 HTML 中实测提取，正则 `station[iI]d\D{0,4}(\d{5})` 唯一命中）。此为后续申请历史观测数据的关键参数。常见误传的 `54715` 经实测**不存在于该页面**，请勿采用。

## 四、⚠️ nmc.cn 版权声明的合规边界（需用户知悉）

nmc.cn 无 robots.txt 限制，但页面明确声明「未经授权禁止下载使用」。这构成一个需要审慎对待的边界：

**本项目的处理原则（已写入代码）**：
1. **不以 nmc.cn 为主数据源**。主采集走 weather.com.cn（其 robots.txt 明确 `Allow: /`，且是中国气象局公共气象服务中心面向公众的服务门户，提供 `d1` 子域即为对外数据服务接口）。
2. **nmc.cn 仅做低频、少量、非商业的补充核验**：每日 1 次城市索引 + 按需 1 次预警查询，远低于任何可能构成负担的频率。
3. **不批量下载、不镜像、不二次分发 nmc.cn 的原始数据文件**；仅提取当日聊城单点的预报要素用于生成文案，并**在文案中注明「数据来源：中央气象台」**——这正是《气象法》第二十五条要求的署名行为，属合法传播而非「下载使用」。
4. **不做任何商业用途**（校园公益服务）。

**⚠️ 需用户确认**：若后续要把 nmc.cn 数据入库长期留存或用于模型训练，属于「下载」范畴，建议改为通过 data.cma.cn 正规申请授权，或先向国家气象中心技术支持邮箱（`nmccn@cma.gov.cn`，实测页面公示）咨询许可。**当前实现不涉及此风险。**

## 五、法规条款核实结果（提示词要求「自行核对现行有效文本，不要照抄」）

提示词 §4.1 那句话被描述为《气象法》的规定但未给条款号。**经核对现行有效文本，该表述出自《气象法》第二十五条，不是第二十二条，且原文用词是「必须」而非「应当」。** 两者区别重要，逐条列出：

### 5.1 《中华人民共和国气象法》（现行有效：2016 年第三次修正）

> 时效性来源：律法网法规库标注「现行有效」，发文字号中华人民共和国主席令第57号，公布/施行日期 2016.11.07
> 修正沿革：1999.10.31 通过 → 2009.08.27 第一次修正 → 2014.08.31 第二次修正 → 2016.11.07 第三次修正
> 来源：https://www.055110.com/law/1/15895.html

- **第二十二条**：「国家对公众气象预报和灾害性天气警报实行**统一发布制度**。各级气象主管机构所属的气象台站应当按照职责向社会发布公众气象预报和灾害性天气警报，并根据天气变化情况及时补充或者订正。**其他任何组织或者个人不得向社会发布公众气象预报和灾害性天气警报。**」
  → **对本项目的约束**：我们**不得自行「发布」气象预报**。本系统定位必须是「传播/转述官方预报 + 生活化解读」，绝不能呈现为自主预报。
- **第二十五条**：「广播、电视、报纸、电信等媒体向社会传播气象预报和灾害性天气警报，**必须使用气象主管机构所属的气象台站提供的适时气象信息，并标明发布时间和气象台站的名称**。通过传播气象信息获得的收益，应当提取一部分支持气象事业的发展。」
  → **对本项目的硬性要求**（已在 `content_generator.py` 中实现）：每条推送文案末尾必须自动附「**信息来源：XX气象台　发布时间：YYYY-MM-DD HH:MM**」，缺一不可。
- **第三十八条**：「违反本法规定，有下列行为之一的，由有关气象主管机构按照权限责令改正，给予警告，可以并处**五万元以下**的罚款：……（二）广播、电视、报纸、电信等媒体向社会传播公众气象预报、灾害性天气警报，**不使用气象主管机构所属的气象台站提供的适时气象信息的**；……」
  → 违法成本明确，必须严格用官方源。

### 5.2 《气象预报发布与传播管理办法》（中国气象局令，2015.05.01 施行，现行有效）

> 来源：中华人民共和国司法部官网 https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/201506/t20150624_145555.html
> **注意**：该办法第十五条明确「2003年12月31日中国气象局公布的《气象预报发布与刊播管理办法》（中国气象局令第6号）**同时废止**」。检索中出现的「刊播管理办法第十条」属**已废止**旧规章，不得作为依据引用。

- **第六条**：「气象预报实行统一发布制度。……**其他任何组织或个人不得以任何形式向社会发布气象预报。**」
- **第九条**：「鼓励媒体和单位传播气象预报。媒体和单位传播气象预报应当使用当地气象主管机构所属的气象台提供的最新气象预报，**并注明气象预报发布的气象台名称和发布时间，不得自行更改气象预报的内容和结论**。」
  → **额外约束（蓝本与提示词均未提及）**：文案生成时**不得修改官方预报的内容和结论**。即可以做「生活化转译」（把「多云转阴」说成「今天云比较多」），但**不得改变或添加预报结论**（如自行断言「明天肯定下雨」）。已作为 `content_generator.py` 的设计红线。
- **🔴 第十条（对深度学习部分构成根本性约束）**：「**科研教学单位、学术团体和个人研究形成的气象预报意见和结论可以提供给气象主管机构所属的气象台制作气象预报时参考，但不得以任何形式向社会公开发布。**」
  → **这是本项目最重要的合规发现。** 提示词 §5.5 原计划「把『模型预测值』与『官方预报值』并列展示在文案中」——**该做法涉嫌违反第十条**：模型输出的气温/降水预测值属「个人/科研教学单位研究形成的气象预报意见和结论」，不得向社会公开发布。
  → **强制修正建议**（需在深度学习阶段执行前由用户确认）：AI 预测值**只用于内部评估与报告**（`reports/04_模型评估报告.md`），**不进入对外推送文案**；对外文案 100% 使用官方预报值。若确需展示模型能力，只能以「历史回测准确率统计」这类**非预报性表述**呈现，且不得给出未来具体数值。
  → 用户本轮已明确「暂不做深度学习部分」，故此风险当前不触发；但**必须在动手做 §5 之前解决**，已记入待确认清单。
- **第十二条**：非法发布气象预报的、向社会传播气象预报不使用当地气象台提供的最新气象预报的，责令改正、警告，可并处**5万元以下**罚款。
- **第十四条**：「……（三）向社会传播气象预报**不注明发布单位名称和发布时间的**；……可以并处**3万元以下**罚款。」
  → 再次印证署名与时间戳是硬性要求，非可选装饰。

## 六、和风天气合规与待用户提供项

- **鉴权形态已变**：实测旧共享域名 `devapi.qweather.com` 返回 403、`geoapi.qweather.com` 返回 404。官方文档（实测可访问）显示新版要求**账号专属 API Host**（形如 `{前缀}.qweatherapi.com`），鉴权支持 **API KEY 或 JWT** 两种方式。
  - 来源：`https://dev.qweather.com/docs/configuration/api-host/`、`https://dev.qweather.com/docs/configuration/authentication/`
- **结论**：**不采用 `py-qweather` SDK**（停滞 25 个月、5 star、未跟进 JWT 与专属 Host），改为直接用 `requests` 封装 REST API。详见报告 01。
- **⚠️ 必须由用户提供的信息**（缺任一项则和风天气通道无法启用，但**不影响主流程**——官方源已足够跑通）：
  1. `和风天气_API_KEY`
  2. `和风天气_API_HOST`（在控制台「项目管理」页可查，形如 `xxxxxx.qweatherapi.com`）
- **拿到 Key 后查询东昌府区 LocationID 的准确方法**（当前 ⚠️ 未核实，不可猜测）：
  ```
  GET https://{你的API_HOST}/geo/v2/city/lookup?location=东昌府&adm=聊城&range=cn
  ```
  返回 JSON 中 `location[].id` 即为所需 LocationID。注意新版 GeoAPI 路径为 `/geo/v2/city/lookup`（挂在专属 Host 下），不再是旧的 `geoapi.qweather.com/v2/...`。
  - 来源：`https://dev.qweather.com/docs/api/geoapi/city-lookup/`
- **和风天气数据的使用边界**：其免费版数据**许可用于非商业开发测试**，但**不得声明为自有预报**；文案中若使用其生活指数，同样应注明数据来源。⚠️ 具体免费额度与商用条款需用户登录控制台确认，本轮未核实（无法在无账号情况下读取订阅条款原文）。
