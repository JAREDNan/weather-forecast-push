## 一、缺陷复述（原 PDF 方案为何必然失败）

原 PDF 方案：**已认证服务号 + wechatpy**，每日 07:30 走「上传封面图 → 创建永久图文素材 → `message/mass/sendall` 群发」。

| 事实 | 官方依据 |
|---|---|
| 服务号（含认证）群发额度 = **每月 4 次**（自然月，手动群发） | 腾讯客服 FAQ：`https://kf.qq.com/faq/120911VrYVrA150921mUbeya.html` |
| 群发次数**官方不支持增加** | 同上 |

**每日 1 次 × 每月 4 次 = 第 5 天额度耗尽，推送中断。** 原 PDF 方案自相矛盾，必须替换。

另核实到两个关键事实（来源同本表与 `reports/02`）：

1. **「发布能力」（draft/add + freepublish/submit）不限次数、不消耗群发额度**，但**用户收不到任何推送通知**，文章仅出现在公众号主页历史消息中 → 不能替代群发实现主动触达。来源：`https://developers.weixin.qq.com/doc/service/guide/product/publish.html`
2. **订阅号每天可群发 1 次**（每天 0 点重置，不累加）→ 唯一同时满足「每日推送 + 用户收到通知 + 零成本 + 个人可注册」的路线。来源：腾讯客服 FAQ 同上。

## 二、候选路线对比表

| 维度 | A. 订阅号每日群发 | B. 服务号模板消息 | C. 企业微信群机器人 | D. 自建 H5 + 菜单跳转 |
|---|---|---|---|---|
| **触达方式** | 主动推送图文，用户收到通知 | 主动推送模板通知 | 推送到企业微信群 | 用户主动点开（被动触达） |
| **每日频率** | ✅ 每天 1 次（0 点重置） | ✅ 日上限 10 万条 | ✅ 20 条/分钟，无月度额度 | ✅ 不限 |
| **账号要求** | 订阅号（个人可注册） | 认证服务号 + 行业类目 | 个人可建群 | 服务号/订阅号均可 + 服务器 |
| **开发成本** | 中（三步流：封面上传→图文→群发） | 低（模板消息接口） | 极低（Webhook POST） | 高（需建站+域名备案） |

| **合规风险** | 无（官方接口） | ⚠️ 天气提醒是否属合规「服务通知」场景**未经官方确认**，有被判违规风险 | 无（官方接口） | 无 |
| **成本** | 免费 | 免费（需认证服务号） | 免费 | 域名+服务器（月几十元） |

## 三、结论与选定结果

**✅ 用户于 2026-10-07 选定：路线 A —— 订阅号每日群发。**

选定理由（按提示词要求如实记录）：

1. **唯一同时满足「每日推送 + 用户收到通知 + 零成本 + 个人可注册」的路线**——订阅号 0 点重置的日群发额度恰好匹配本系统每天 1 次的设计。
2. 服务号每月 4 次额度**结构性不匹配**每日推送，不可选。
3. 模板消息存在「天气提醒是否合规」的官方未确认风险，且需要认证服务号门槛更高，列为备选。
4. 企业微信群机器人触达范围限群成员，作为校内班级/社团群的**补充渠道**保留（代码已支持 `wecom_webhook` 路线，可随时切换）。

**上线前置条件（待用户提供）**：
- 订阅号 AppID / AppSecret → 填入 `.env`（模板见 `.env.example`），并设置 `WECHAT_PUSH_CHANNEL=subscription`

## 四·补（2026-10-19 实测修正：选定路线受账号类型限制，已分流）

> ⚠️ **重要更正**：本文档第三节「已选定订阅号每日群发」为设计结论，但**实测发现
> 账号类型限制使其无法用 API 自动执行**，必须如实修正如下。

### 4.1 实测事实（2026-10-19，订阅号 AppID 已脱敏）

| 接口 | 实测结果 | 官方依据 |
|---|---|---|
| access_token | ✅ 可用（IP 白名单 111.36.110.55 已配置） | 基础接口 |
| user/get 用户列表 | ❌ 48001 api unauthorized | 仅认证账号可用 |
| media/uploadnews 素材上传 | ❌ 48001 api unauthorized | 仅认证账号可用 |
| mass/sendall 群发 | ❌ 48001 api unauthorized | 仅认证账号可用 |

**根因**：当前公众号为**个人主体·未认证订阅号**。微信自 **2025-07** 起回收
「个人主体账号、企业主体未认证账号」的发布/群发等接口调用权限
（官方公告：developers.weixin.qq.com/community 2025-07 通知）。
因此**代码无法自动向公众号粉丝群发**——这是平台硬规则，与代码实现无关。

### 4.2 分流后的实际推送架构（2026-10-19 起生效）

| 通道 | 触达 | 自动化 | 状态 |
|---|---|---|---|
| **企业微信群机器人**（wecom_webhook，.env 已配置） | 群成员 | ✅ 全自动 | ✅ 已实测推送成功（10-19） |
| **公众号网页手动群发**（`--gzh-pack` 生成推送包，人工粘贴） | **全部关注者** | 每日人工约 1 分钟 | ✅ 已实现（10-19），待首次人工发布 |
| 公众号 API 群发 | 全部关注者 | ✅ 全自动 | 🔒 受账号类型限制，暂不可用 |

### 4.3 未来的两条解锁路径

1. **完成微信认证**（需企业/个体工商户/政府/媒体等**非个人主体**资质，300 元/年）：
   认证后 user/get、素材上传、群发接口全部解锁，可切回
   `WECHAT_PUSH_CHANNEL=subscription` 实现全自动 API 群发（订阅号每天 1 次）。
2. 无资质时维持现状：企业微信自动推送（群内）+ 公众号手动群发（全粉丝）双通道并行。

**结论**：原「订阅号每日群发」设计在认证前**降级为「推送包 + 人工群发」**，
全自动能力由企业微信群机器人承担；待认证后再回归全自动。
