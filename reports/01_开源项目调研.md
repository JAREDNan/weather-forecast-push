## 推荐复用组合

- **推送层**：`wechatpy/wechatpy`（MIT，2026-05 仍活跃，微信公众号官方 Python SDK，支持模板消息/客服消息/素材群发）
- **调度层**：`agronholm/apscheduler`（MIT，2026-10 仍活跃，Python 定时调度事实标准）
- **数据层**：**不用第三方 SDK，直接用 `requests`/标准库 `urllib` 封装官方 REST 接口**。理由见下方深挖结论 1。

## 关键深挖结论

### 1. py-qweather 可用性 → 不采用，直接 requests 封装

- PyPI 包 `pyqweather` 最新版发布于 2024-08，GitHub 仅 5 star、最后推送 2024-09（停滞 25 个月）。
- 和风天气官方已改版：新版要求每个账号使用**独立 API Host**（形如 `{专属前缀}.qweatherapi.com`），不再是统一 `devapi.qweather.com`；鉴权从单纯 Key 扩展到 JWT。
- 实测（无 key）：`https://devapi.qweather.com/v7/weather/3d` 返回 **403**；`https://geoapi.qweather.com/v2/city/lookup` 返回 **404**——印证旧共享域名已不可直接裸调。
- 该 SDK 未跟进 JWT 认证与独立 Host 机制，引入即背上维护包袱。**结论：自行用 requests 封装和风 REST API（约 50 行），可控且无额外依赖。**
- 来源：和风天气官方文档 dev.qweather.com/docs/configuration/api-host/ 与 /authentication/（实测 200 可访问）。

### 2. EverydayWechat 推送通道 → 🔴 itchat 个人号协议，完全不可复用

- 该项目基于 `itchat`（网页版微信协议）开发，README 自述「依赖网页版微信，若无法登录则无解」。
- itchat/wxpy 走个人号网页版协议，2019 年后微信大规模封禁，新号几乎全部无法登录。
- 与本项目要用的「已认证服务号官方 API」是完全不同的技术路线。**推送逻辑不可复用，仅其天气文案模板可作思路参考。**

## 缺口清单（需自研）

1. **多源气象数据采集层**：weather.com.cn / nmc.cn 官方接口封装 + 和风天气生活指数补充，含限速、熔断、降级链。无现成合规开源覆盖。
2. **人性化中文气象文案生成器**：把多源 JSON 转成校园场景友好播报，含《气象法》要求的「信息来源 + 发布时间」自动附注。
3. **微信推送适配层**：wechatpy 提供底层 API，但每日推送的消息结构、路线选型（见报告 02 与 §3.3）需自建。
4. **一体化调度胶水层**：采集 → 生成 → 推送 → 落库的每日主流程。
5. **聊城/东昌府区标识映射**：需固化正确城市代码（见报告 02，已纠正蓝本错误）。
